# Завдання

Health-check guard (`fixture/guard.py`) щохвилини перевіряє статус двох
messaging-інстансів через instance API. Обидва зараз показують `close` вже
понад годину. У системному логі видно, що `restart_instance()` реально
виконується на кожному циклі перевірки — але жодного Telegram-алерту про
ескалацію (після `ALERT_AFTER_ACTIONS` спроб) так і не прийшло, і жоден
інстанс не відновився.

Прочитайте `fixture/guard.py` повністю й поясніть точний механізм. Відповідь
має:

1. назвати конкретну функцію та рядок, де рестарт викликається без
   очікування готовності інстансу;
2. пояснити, чому `state.json` (`down_streak`/`action_count`) фактично
   ніколи не просувається за поріг, попри те, що restart реально
   виконується щоцикл;
3. спростувати версію, що причина — заниженні `DOWN_STREAK_THRESHOLD` чи
   `ALERT_AFTER_ACTIONS` (обидва встановлені розумно, підняти їх нічого не
   змінить);
4. навести щонайменше дві цитати `fixture/guard.py:рядок`.
